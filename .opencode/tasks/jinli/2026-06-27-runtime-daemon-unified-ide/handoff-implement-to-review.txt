## Design Decisions (carry into review)
- `is_alive()` requires `loop_alive AND recorded_alive` (tightened so a freshly-claimed daemon does not falsely report alive before health loop starts)
- Endpoint port is informational only in WP01 (no actual bind); WP03 turns it into live HTTP/IPC
- `daemon.lock` advisory lock file NOT created; (PID, endpoint) pair is the lock
- `daemon_state` derivation: `online` if loop_alive and no required blockers, else `degraded`; `stopping`/`stopped` only via explicit transitions; `offline` when no PID file
- `start()` performs an initial `registry.refresh_all()` synchronously so first `status -Json` is `online` not `starting`
- `read_status_snapshot()` re-probes PID liveness to override stale `online` snapshot when worker crashed
- PowerShell wrapper uses `System.Diagnostics.Process` (not `Start-Process -Wait`) to avoid hang on detached worker spawn
- `_cli_start` uses `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP` (0x00000008 | 0x00000200) so worker survives controller exit
- `STOP_FLAG_TIMEOUT_S = 5.0`; `_terminate_windows` is the only escalation path on Windows
- Test isolation via `JINLI_DAEMON_STATE_DIR` env var (set in `_isolated_state_dir` context manager, restored on teardown)
